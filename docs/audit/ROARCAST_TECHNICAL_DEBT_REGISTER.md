## Technical Debt Summary

This register tracks all software engineering vulnerabilities, architectural design smells, code duplication, security exposures, and process limitations discovered during the repository-wide audit of RoarCast. Every item is classified by severity, priority, effort, dependency requirements, and practical mitigation instructions to support future technical roadmaps and project staging.

### Severity & Priority Definitions
*   **Severity Scale:** Critical (System failure or data exposure risk) | High (Core architectural defect or broken capability) | Medium (Maintainability or performance friction) | Low (Minor code smell or UI defect) | Informational (Documentation or styling refinement).
*   **Priority Schedule:** **P0:** Must fix immediately (blocks safe staging) | **P1:** Must fix before controlled pilot | **P2:** Should fix before city-wide rollout | **P3:** Improvement or optimization | **P4:** Future optional enhancement.
*   **Effort Estimation:** **XS:** (< 2 hrs) | **S:** (Half day) | **M:** (1–2 days) | **L:** (3–5 days) | **XL:** (> 1 week).
