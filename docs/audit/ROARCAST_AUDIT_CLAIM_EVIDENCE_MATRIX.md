## Evaluation Methodology & Classification Schedule

Every material claim made across the original five audit documents (`ROARCAST_SOFTWARE_ENGINEERING_AUDIT.md`, `ROARCAST_TECHNICAL_DEBT_REGISTER.md`, `ROARCAST_ARCHITECTURE_RECOMMENDATION.md`, `ROARCAST_REFACTORING_ROADMAP.md`, and `ROARCAST_AUDIT_SUMMARY.md`) was subjected to static codebase search, line-by-line file reading (`view_file`, `.NET ReadAllLines`), and automated verification commands (`npm list`, `npx tsc`). 

### Classification Taxonomy
*   **VERIFIED:** Repository code, package configuration, and line numbers provide irrefutable proof supporting the statement as factually exact.
*   **PARTIALLY VERIFIED:** The core premise is true, but specific file path citations, numeric counts, or contextual qualifiers in the original text contained minor inaccuracies.
*   **UNVERIFIED:** Cannot be proven or disproven by current static repository contents without running unmeasured external instrumentation (e.g., dynamic runtime memory profiles).
*   **INCORRECT:** Direct code evidence contradicts the claim or reveals technical imprecision (e.g., asserting that `"use client"` disables server-side HTML pre-rendering).
*   **OUTDATED:** Refers to hackathon presentation documentation that is superseded by actual application source files.
*   **OPINION / RECOMMENDATION:** Represents architectural design judgment or governance guidance rather than an empirical repository feature assertion.
